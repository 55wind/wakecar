# 일어나차 화면 가안 설계 문서 (Pleos Connect 기반 탐색안)

작성일: 2026-11-15
대상: 일어나차(WakeCar) Compose 앱 `ui/WakeCarScreen.kt`의 재설계 가안
산출물: `proto/index.html` (HTML 시안, 브라우저에서 바로 열림), 이 문서

## 현재 캐릭터와 앱 반영 상태 (2026-11-15)

자동차 몸체 캐릭터는 폐기했다. 동그란 생물이 주인공이고 자동차와 수면 요소는 소품으로만 남긴 원작 캐릭터 네 종(콩콩, 폭신, 빵삐, 몽실)을 봉제 인형 질감의 3D로 만들었다. 자세한 내용은 `CHARACTER.md`를 따른다. 아래 "최초 가안" 절의 자동차 마스코트 설명은 역사 기록이다.

이 문서의 화면, 소리, 캐릭터, 키우기 설계는 Compose 앱에 옮겼다(`app/src/main/java/kr/contest/wakecar/ui`, `audio/SoundEngine.kt`, `core/Growth.kt`, `settings/AppSettings.kt`). 캐릭터 그림과 소리는 이 폴더의 스크립트로 만들어 앱 자산으로 내보낸다(`design/README.md`).

## 캐릭터, 키우기, 해 이동 (2026-11-15)

캐릭터는 `CHARACTER.md`를 따른다. 아래는 화면 동작 규칙이다.

- 키우기(`proto/grow.js`): 낮잠을 잘 자고 잘 일어나면 캐릭터가 자란다. 경험치는 낮잠 성공 40(한 번에 일어나면 +10, 15초 안에 일어나면 +10), 스스로 끝낸 낮잠 10, 쓰다듬기 2(하루 10번까지). 별사탕은 낮잠 성공 30, 오늘의 할 일 보상, 쓰다듬기 1. 레벨마다 필요한 경험치는 50 + 30 x (레벨 - 1). Lv1~2 아기, Lv3~5 꼬마, Lv6 이상 어른이며 단계마다 크기가 커진다. 기분은 쓰다듬기 +5, 낮잠 +15, 시간당 -4. 졸음은 마지막 낮잠 뒤 시간당 +12이고 70 이상이면 캐릭터가 졸린 표정과 "콩콩이도 졸려해요" 인사로 낮잠을 권한다. 캐릭터마다 레벨과 옷장은 따로, 별사탕과 졸음, 오늘의 할 일은 함께 쓴다.
- 화면: 시작과 끝 화면 장면 오른쪽 위에 상태 띠(레벨, 단계와 이름, 경험치 막대, 별사탕). 누르면 키우기 창(상태, 오늘의 할 일, 옷장). 끝 화면에 받은 보상, 레벨이 오르면 장면 위 축하 알림. 시뮬레이터 탭으로 바로 들어온 끝 화면은 보상을 주지 않는다.
- 해: 동쪽(왼쪽) 지평선에서 떠서 서쪽(오른쪽)으로 진다. 시작 화면은 실제 시각 위치, 잠들면 서쪽으로 지고 깨우기 1단계부터 동쪽에서 다시 뜬다. 해는 거꾸로 움직이지 않는다. 시뮬레이터 "해 뜨고 지기"는 14초 동안 하루를 보여 준다.
- 글자 배치 점검(`scripts/check_layout.py`): 화면 6종 x 방향 2종 x 크기 3종과 설정, 키우기 창. 반영한 것: 미션 문장을 실제 줄 너비로 맞춘 카드, "두 번" 사이 줄바꿈 금지, 깨우기 1단계 이름 단축, L 12.9형 가로 압축, 세로 화면 주 버튼 아래 고정, 세로 화면 캐릭터 위치, 복귀 시각 단추 "− 5분 / + 5분". 남은 표시는 세로 화면에서 고정 버튼 아래로 내용이 스크롤되며 겹치는 것뿐이다.
- 점검 스크립트: `check_chars.py`(캐릭터 선택, 표정, 그림자, 끌기 방향, 키우기, 해), `check_audio.py`, `check_features.py`, `check_layout.py` 모두 통과.

## 소리 설계 v2 (2026-11-15)

설정을 "깨울 때"와 "잠들 때" 두 묶음으로 나눴다. 설정은 브라우저 저장소(`wakecar-audio`)에 남고, 준비 화면의 "깨우는 소리" 줄과 자는 중 화면 문구, 깨우기 1단계 이름에 바로 반영된다. 소리는 모두 Web Audio로 합성한 원작이다(`proto/audio.js`).

- 알람 소리 4종: 해 뜨는 피아노, 새벽 숲, 오르골, 출발 신호. 거슬리는 단음 대신 선율형으로 만들었다. 선율형 알람이 깬 직후의 수면 관성을 덜 느끼게 한다는 보고(McFarlane et al., 2020, PLoS ONE)를 근거로 삼았다.
- 깨우기 단계와 연동: 1단계(깨우기 3분 전, 시연은 6초 전)는 아주 작고 멀게(잔향 많음) 시작해 서서히 키운다. 2~4단계는 층 음량 0.5, 0.75, 1.0, 빠르기 분당 84, 100, 120박, 잔향은 줄여 소리가 가까워진다. 단계가 오르면 음역, 화음, 경적 같은 요소가 더해진다.
- "점점 크게 깨우기"를 끄면 1단계에는 소리를 내지 않고, 2단계부터 최대 음량으로 울린다.
- 알람 최대 음량과 수면 음악 음량을 따로 둔다. 미리듣기는 1~4단계를 4초씩, 16초로 압축해 들려준다.
- 수면 음악 5종: 고요한 피아노(분당 60박에서 52박으로 느려짐), 느린 앰비언트, 창밖의 빗소리, 파도 호흡(분당 6회에서 5회), 달리는 차 안. 수면 버스는 2.4kHz 위를 깎아 밝은 소리를 줄였다.
- "잠들면 서서히 줄이기": 낮잠 길이의 절반(최대 10분) 동안 수면 음악을 30%까지 내린다. 1단계가 시작되면 수면 음악은 알람으로 교차해 넘어간다.
- 점검: `scripts/check_audio.py`가 설정 반영, 새로고침 뒤 유지, 알람 4종의 단계별 실제 출력 크기 증가, 미리듣기 단계 표시를 확인한다. 실제 차량 스피커 음량, 운전석 배치, Pleos 오디오 포커스 정책은 검증하지 않았다.

## 현재 시연판 변경 사항

현재 배포 파일은 `wakecar-demo.html`이다. CSS, 동작 코드, 아이콘을 포함하므로 HTML 파일 하나로 실행할 수 있다. Asta Sans 웹폰트를 불러오지 못하면 시스템 글꼴로 표시한다. 영상은 제공하지 않는다.

- 알라미와 Sleep Cycle 참고 화면을 바탕으로 밤, 새벽, 아침 배경과 자동차 캐릭터를 반영했다.
- 눈 옆 보라색 안대 부품은 사용자 요청으로 제거했다. 지붕 위 안테나는 유지했다.
- 사람과 좌석 장면은 자동차 캐릭터로 교체했다. 눈꺼풀, 안테나 전구, 브레이크등, 와이퍼, 창문과 바퀴가 상태에 반응한다.
- 흰 미션 카드와 어두운 반투명 텍스트 영역을 사용한다. 배경 일러스트 색은 탐색용이며 Pleos 공식 토큰으로 검증한 색이 아니다.
- 가로 화면의 시간과 남은 분은 120px이다. Pleos 기본 글자 위계 밖의 탐색 값으로, 팀의 검토가 필요하다.
- 여섯 화면의 동작, 기어 D 시작 차단, 미션, 확인 질문, 휴식과 3초 비상 종료를 브라우저에서 확인했다. 작은 세로 창에서 깨우기 화면의 비상 종료 버튼도 보이도록 조정했다.
- 차량 상태와 기록은 브라우저 메모리의 시뮬레이션이다. 실제 Vehicle SDK 연결, 주행 제한, 영구 저장과 성능 기준은 검증하지 않았다. 주간 테마는 별도 구현이 필요하다.

아래 내용은 최초 가안의 근거 및 이식 메모다. 사람 장면, 60dp 상한, 회색조 배경과 관련된 설명은 위 변경 사항으로 대체한다. 이 시안은 Pleos 심사를 통과했음을 의미하지 않는다.

## 1. 가안의 목적과 범위

현재 앱은 남색과 보라 바탕에 보라에서 남색으로 이어지는 그라데이션 버튼, 알약 모양 버튼, 화면 폭에 맞춘 배율 확대(`DESIGN_WIDTH_DP = 1280`)를 쓴다. 이 가안은 세 가지를 바꾼다.

1. 색, 글자, 모양, 컨트롤 치수를 Pleos Connect UI Design Guide 2.1.5와 현대차 제공 Figma 원본(`Pleos_Connect_design_assets_215.fig`, `Pleos_Connect_display_guide_215.fig`)의 값으로 맞춘다.
2. 앱 기획·설계 가이드가 요구하는 portrait와 landscape 두 레이아웃, 그리고 Connect-S 17형부터 Connect-L 12.9형까지의 창 크기에서 깨지지 않게 한다.
3. 행동마다 그 행동을 설명하는 모션을 붙인다. 모션은 DesignBookmark Motion의 스프링 값을 그대로 쓰고, 사람이 자고 깨는 장면을 하나 더해 앱의 상태를 한눈에 보이게 한다.

앱의 문구, 흐름, 안전장치(정차 확인, 미션, 다시 잠들기 방지, 휴식 권장)는 바꾸지 않았다. 문구는 기존 Compose 코드의 것을 그대로 옮겼다.

## 2. 실행 방법

`proto/index.html`을 브라우저로 연다. 위쪽 조작 막대는 시안 확인용이며 앱 화면에는 들어가지 않는다.

| 조작 | 하는 일 |
|---|---|
| 화면 | 여섯 화면으로 바로 이동 |
| 창 크기 | 가로 2:0(앱 하나), 세로 1:1(앱 둘) |
| 화면 크기 | Connect-S 17형, S 14.6형, L 12.9형의 앱 창 크기(dp) |
| 차량 신호 | Virtual Console 대신 브레이크, 와이퍼, 창문, 문, 기어 신호를 넣음 |

흐름은 앱의 시연 모드(`NapTimings.DEMO`)와 같은 시간으로 진행된다. 낮잠 1분은 2초, 3단계는 알람 8초 뒤, 4단계는 20초 뒤, 확인 질문 대기와 휴식은 각 20초이다. 시작 화면에서 "정차 중이에요. 낮잠 시작"을 누르면 끝 화면까지 실제로 이어진다. 주소 뒤에 `?phase=WAKING&orient=port&size=l129`처럼 붙이면 해당 화면과 크기로 바로 열린다.

## 4. 가이드 준수 대응표

| 가이드 요구 | 출처 | 가안의 대응 |
|---|---|---|
| 운전 중 동영상, 움직이는 이미지, 자동 스크롤 금지 | UI 가이드 소개, 주의 분산 가이드 | 앱은 기어 P와 속도 0에서만 동작하고, 차가 움직이면 낮잠을 끝낸다. 반복 모션(숨쉬기, 바람)은 자는 중과 쉬는 시간에만 돌고, 둘 다 정차 상태이다. 자동 스크롤은 없다 |
| 한 손 조작, 손발을 움직이게 유도하지 말 것 | UI 가이드 소개 | 깨어남 미션은 브레이크, 와이퍼, 창문 조작을 요구한다. 이는 정차 중 각성 확인을 위한 의도적 설계이므로 예외 근거를 심사 서류에 적어야 한다(8절 결정 사항 1) |
| 1~2초 안에 파악, 핵심 정보만 | 즉시성 | 화면마다 가장 큰 글자는 하나뿐이다(깨울 시각, 남은 분, 미션, 질문, 휴식 안내, 끝 인사) |
| 입력 후 0.25초 안에 응답 | 즉시성 | 모든 버튼은 누르는 순간 95% 축소와 색 변화로 응답한다(120ms). 스프링은 첫 프레임부터 움직인다 |
| 대비 4.5:1 이상 | 색상 및 대비 | 본문은 흰색 100%, 84%, 64%만 쓴다. 64%(#AEAEAF 상당)도 배경 #1D1E21 대비 약 7.6:1이다. 32%는 비활성 표시에만 쓴다 |
| 문장 3줄 이하, 한 줄 80자 이하 | 글꼴 및 가독성 | 기존 문구를 유지하면서 가장 좁은 portrait 창에서도 3줄을 넘지 않는다. 한국어는 어절 단위로 줄을 바꾼다(`word-break: keep-all`) |
| 중요 글자 5mm, 보조 3mm | 글꼴 및 가독성 | 17형 기준 1dp는 약 0.146mm이다. Headline 60dp의 한글 높이는 약 6mm, Label 20dp는 약 2.9mm라 보조 글자는 Label M 24dp(약 3.5mm) 이상을 쓴다 |
| 아이콘은 글자와 함께 | 아이콘 및 피드백 | 상태 표시(체크, 경고)는 항상 글자와 같이 나온다. 색만으로 상태를 전하지 않는다 |
| 주간과 야간 모드 | 유연성 | 이번 가안은 다크 테마만 그렸다. 토큰은 Pleos의 light와 dark 짝을 그대로 쓰므로 라이트 테마는 값 교체로 추가된다 |
| 다국어 | 확장성 | 글자가 길어져도 버튼과 행은 높이가 늘지 않고 줄바꿈으로 흡수한다. 고정 폭 문구 상자는 없다 |
| portrait와 landscape 각각 설계 | 앱 구조와 화면 모델 | 모든 화면에 두 레이아웃을 둔다. portrait는 핵심 기능(시각, 미션, 버튼)을 먼저, landscape는 확인 목록과 장면을 옆 열에 더한다 |
| 다양한 해상도 대응 | 확장성, 창 정책 | 기존 코드의 화면 폭 배율 확대를 없애고 dp 원값을 쓴다. 대신 창 크기에 따라 열 수가 바뀐다 |
| 큰 터치 영역, 높은 대비, 텍스트 최소화 | 주의 분산 가이드 | 버튼 80dp와 100dp, 세그먼트 84dp, 스위치는 보이는 크기 80 x 48dp에 사방 16dp 터치 여유를 더했다 |
| 알림은 필요할 때만 | 알림 | 토스트를 쓰지 않는다. 결과가 화면에 보이면 따로 알리지 않는다 |
| 일관성: 기본 탑재 UI와 같은 패턴 | 일관성 | 버튼, 세그먼트, 스위치, 패널, 페이지 내비게이션(앱 아이콘과 제목)을 Pleos 컴포넌트 모양으로 바꿨다. 알약 버튼과 원형 스위치 손잡이는 쓰지 않는다 |
| 정차 중 CPU 25% 이하, RAM 400MB 이하 | 성능 | 스프링 엔진은 모든 값이 멈추면 프레임 루프를 멈춘다. 반복 모션은 CSS(Compose에서는 `infiniteTransition` 하나)로 처리한다 |

## 6. 화면별 설계

| 화면 | 가장 큰 정보 | landscape 구성 | portrait 구성 |
|---|---|---|---|
| 1. 시작 | 깨울 시각(시연 모드에서는 초) | 왼쪽: 장면, 시각, 길이 선택, 시작 버튼. 오른쪽: 시작 전 확인, 차가 해 주는 일, 두 스위치 | 같은 순서를 한 열로. 확인 목록은 시작 버튼 아래 |
| 2. 자는 중 | 남은 분 | 가운데 장면과 남은 분, 오른쪽 아래 "그만 자기" | 같음 |
| 3. 깨우기 | 미션 문장 | 왼쪽: 미션과 진행 줄. 오른쪽: 장면, 깨우기 단계, 비상 종료 | 장면을 빼고 미션, 단계, 비상 종료 순 |

## 7. 모션 사양

### 7.1 원칙

1. 모션은 상태를 설명할 때만 쓴다(Pleos Animation: "사용자에게 상태 설명을 위한 목적"). 장식으로만 움직이는 요소는 없다.
2. 앱이 동작하는 동안 차는 늘 정차 상태이므로 주행 중 모션 제한에 걸리지 않는다. 그래도 반복 모션은 두 개(자는 중 숨쉬기, 쉬는 시간 바람)로 제한한다.
3. 모든 버튼은 Pleos Button interaction을 따른다: 누르면 95%로 줄고 배경이 한 단계 바뀌며, 손을 떼면 돌아온다.
4. 시스템의 "동작 줄이기" 설정이 켜지면 스프링은 임계 감쇠로 바뀌어 튀지 않고, 반복 모션과 화면 전환 움직임은 꺼진다. 상태 변화 자체는 그대로 보인다.

### 7.2 행동별 모션과 스프링 값

스프링 값은 DesignBookmark Motion 원본(`motion-src/*/`)의 "강성 감쇠"를 그대로 옮겼다. 질량은 1이다. Compose에서는 `spring(dampingRatio = 감쇠 / (2 * sqrt(강성)), stiffness = 강성)`으로 같은 움직임이 된다.

| 행동 | 참고 모션 | 움직임 | 강성 / 감쇠 | Compose dampingRatio |
|---|---|---|---|---|
| 낮잠 길이 고르기 | Segmented control | 흰 선택 칸이 미끄러지고, 빠를수록 가로로 늘었다 돌아옴 | 300 / 20 | 0.58 |
| 깨울 시각이 바뀜 | Word roll, Number stepper | 바뀐 숫자만 아래에서 올라옴(늦어지면 위로), 자리마다 28ms 차이 | 260 / 24 | 0.74 |
| 돌아갈 시각 5분 앞뒤 | Number stepper | 같은 방식, 방향은 앞으로면 아래로 | 260 / 24 | 0.74 |
| 스위치 켜고 끄기 | Toggle switch | 손잡이가 가는 쪽으로 늘어났다가 튕기며 자리 잡음, 트랙 색이 섞이며 바뀜 | 위치 320 / 18, 늘어남 300 / 20 | 0.50, 0.58 |
| 미션 한 단계 수행 | Step progress | 진행 줄이 늘고, 점이 노랗게 차고, 체크가 그려지고, 점이 톡 튐 | 줄 160 / 22, 채움 260 / 24, 체크 140 / 20, 튐 500 / 14 | 0.87, 0.74, 0.85, 0.31 |
| 깨우기 단계가 오름 | Step progress (세로) | 새 단계 점이 70%에서 튀어 오름 | 500 / 14 | 0.31 |
| 비상 종료 길게 누르기 | Hold button | 3초 동안 왼쪽부터 채워지고 글자가 채움 아래서 반전. 일찍 떼면 되돌아가며 좌우로 흔들림 | 되돌림 260 / 14, 누름 520 / 20, 흔들림 700 / 9 | 0.43, 0.44, 0.17 |
| 낮잠을 마침 | Loading to success | 초록 원이 60%에서 커지고 체크가 그려짐 | 원 300 / 22, 체크 120 / 20 | 0.64, 0.91 |
| 남은 시간 막대 | (선형) | 1초마다 선형으로 줄어듦. 시간이므로 스프링을 쓰지 않음 | | `tween(1000, LinearEasing)` |

원본과 다른 점은 두 가지이다. 원본 Hold button은 3초가 아니라 1.2초이며, 앱의 기존 규칙(3초 길게 누르기)과 Pleos Long press(2~3초)에 맞춰 늘렸다. 원본 Toggle switch와 Hold button은 폭(width)을 애니메이션하지만, 가안은 레이아웃을 다시 계산하지 않도록 같은 움직임을 `scaleX`로 바꿨다.

### 7.3 사람 장면 (자고, 깨고, 일어나는 모션)

좌석에 앉은 사람을 도형으로만 그린 장면이 모든 화면을 따라다닌다. 장면의 움직임은 장식이 아니라 실제 차와 낮잠 상태를 그대로 옮긴 것이다.

| 낮잠 사건 | 장면의 변화 | 스프링(강성 / 감쇠) |
|---|---|---|
| 시작 화면 | 등받이를 세우고 앉아 눈을 뜨고 있음 | |
| 낮잠 시작 | 등받이가 뒤로 젖혀지고(운전자가 직접 젖히는 동작), 고개가 숙여지고, 눈이 감김 | 등받이 60 / 14, 고개 120 / 16, 눈꺼풀 420 / 32 |
| 자는 중 | 가슴이 5.2초 주기로 천천히 부풂(숨쉬기). 장면 전체가 어둡게 가라앉음 | CSS 반복 |
| 1단계 조명 밝히기 | 앞유리 너머로 해가 천천히 떠오르고 하늘이 노랗게 물듦. 화면 위쪽에도 같은 빛이 번짐 | 해 14 / 7.5(임계 감쇠, 튀지 않음) |
| 2단계 알람 | 머리가 움찔하고 눈이 반쯤 뜨임 | 움찔 700 / 9 |
| 3단계 | 한 번 더 움찔. "등받이 일으키기"가 켜져 있으면 등받이가 실제로 조금 세워짐 | 등받이 60 / 14 |
| 4단계 | 더 크게 움찔, 눈이 더 뜨임 | 700 / 9 |
| 미션 한 단계 | 단계마다 눈이 더 뜨이고 등받이가 조금씩 올라옴 | |
| 확인 질문 | 똑바로 앉아 화면 쪽을 봄. 답할 때마다 눈동자가 왔다 갔다 함 | 눈동자 280 / 22 |
| 쉬는 시간 | 창문이 내려가고 바람 줄기가 지나감, 사람은 창밖을 봄 | 창문 90 / 18, 바람 CSS 반복 |
| 끝 | 창문이 올라가고 두 팔을 위로 뻗어 기지개를 켬 | 팔 220 / 18 |
| 다시 잠듦(확인 시간 초과) | 다시 젖혀지고 눈이 감긴 뒤 새 미션으로 깨움 | |

장면은 화면 낭독기에서 숨긴다(`aria-hidden`). 장면이 전하는 정보는 모두 글자로도 화면에 있기 때문이다.

## 8. 팀이 결정할 사항

1. 미션이 손발 조작을 요구하는 점. UI 가이드는 "운전자의 손이나 발을 움직이는 동작을 유도해서는 안 된다"고 적는다. 일어나차는 정차 중 각성 확인이 목적이므로 정당화할 수 있지만, 심사 서류에 근거(정차 조건, CarUxRestrictions 확인, 차가 움직이면 즉시 종료)를 명시하는 편이 안전하다.
2. 깨울 시각의 크기. 기존 앱은 120sp로 매우 크게 보였다. 가안은 Pleos 위계의 상한인 Headline L 60dp를 지켰다. 젖힌 좌석에서 멀리 보는 상황을 고려해 더 키우려면 위계 밖 예외가 되므로 팀 판단이 필요하다.
3. 자는 화면의 밝기. 대비 기준을 지키기 위해 글자를 흰색 64%로 두었다. 눈부심이 문제라면 글자 대비를 낮추기보다 시스템 밝기와 야간 모드에 맡기는 쪽을 권한다.
4. 앱 아이콘. 현재 런처 아이콘은 Vehicle SDK 샘플 아이콘으로 보인다. Pleos App Icon 가이드(Adaptive Icon, Foreground와 Background 분리, design assets의 그리드 템플릿)에 맞춘 전용 아이콘이 필요하다.
5. 라이트 테마. Pleos는 주간과 야간 모드를 요구한다. 토큰 짝은 이미 정리되어 있으므로 라이트 값을 채우는 작업만 남았다.
6. 다크 테마의 보조 버튼 색. Figma 컴포넌트에는 라이트 테마 값만 들어 있어, 다크의 보조 버튼은 웹 문서의 surface_high(#313236)로 해석했다. Pleos 기술 지원에 확인할 항목이다.

## 9. Compose 이식 메모

1. `DESIGN_WIDTH_DP` 배율 확대를 제거하고 dp 원값을 쓴다. 대신 `BoxWithConstraints`의 폭으로 1열(840dp 미만)과 2열을 고른다.
2. `Tone`과 `Type` 객체를 5절 표의 값으로 바꾼다. 버튼 모양은 `RoundedCornerShape(32.dp)`(Large), `RoundedCornerShape(24.dp)`(Medium)이며 `Pill`은 쓰지 않는다.
3. 스프링 예: 세그먼트 선택 칸은 `animateDpAsState(target, spring(dampingRatio = 0.58f, stiffness = 300f))`, 스위치 손잡이는 `spring(0.50f, 320f)`.
4. 누름 효과는 `Modifier.graphicsLayer { scaleX = s; scaleY = s }`에 `interactionSource.collectIsPressedAsState()`로 0.95를 준다.
5. 비상 종료는 기존 `withTimeoutOrNull(3000)` 로직을 유지하고, 누르는 동안의 진행률만 `Animatable`로 그린다.
6. 사람 장면은 `Canvas` 하나에 회전과 이동 값만 넘기면 된다. 숨쉬기는 `rememberInfiniteTransition`을 자는 화면에서만 만든다.
